# Title Maintenance

This supplement owns process-wide automatic title generation under the package rigor declaration.
The [thread feature](../../../doc/features/conversation-threads/design.md#thread-titles) owns
visible eligibility, precedence and strict validation. Syndic owns intrinsic attributes, selected
history and source preparation; backend owns authenticated session/stream primitives. This owner
never creates a Syndic turn, catalog row, CAS display name or window-owned generation task.

## Readiness Gate

Automatic generation is deferred under the feature's accepted
[availability limit](../../../doc/features/conversation-threads/design.md#automatic-title-generation-availability).
Do not mount title-maintenance preparation, discovery or invocation during this rework. The
remaining contract describes requirements for a future separately qualified implementation;
it does not require CAS modification or block the remaining rework.

Production invocation is blocked until an enforced inference-only maintenance capability is
specified and qualified against the pinned backend. Full-profile notification admission and
developer instructions do not establish that capability. The current ephemeral-thread path
inherits configured execution permissions; rejecting a later tool event cannot prevent an effect
already performed. Read-only filesystem sandboxing alone does not exclude configured MCP writes,
subagent activity or extension hooks. Do not mount this worker under inherited permissions.

Operator approved an inference-only capability admitting bounded inference with no shell/tool dispatch, MCP/app calls,
subagent creation or configured execution hooks before they can act. This needs an explicit
backend-owned enforcement and qualification contract; it is not a prompt, empty dynamic-tool list
or new name for ordinary admission. Exact-source inspection of both the documented 0.146.0
contract and actual official 0.163.0 runtime found no qualifying public policy. The latter's
internal tool ceiling does not establish public admission or hook/startup isolation. The
[extension proposal](../../../doc/audits/title-maintenance-inference-only-proposal.md) is historical:
Operator ruled out CAS modification for this work. Retain history-derived titles and revisit the
[known limitation](../../../doc/known-limitations.md#automatic-thread-titles) after the rework is
otherwise finished. The concrete invocation contract below requires reconciliation if a future
supported capability becomes available. No production title implementation is accepted.

## Source And Admission

Only ordinary threads without an accepted generated title are automatic candidates. Discussion
threads retain their existing branch-local history fallback. Draft, synthetic context, inherited
branch input, provider operations and lifecycle continuation are not generation sources.

Syndic supplies a resumable typed preparation of the earliest eligible real user input on the
current selected path. It binds the exact Home generation, thread/attributes revisions, path
digest, source turn, sealed content reference/digest and immutable execution binding. App receives
at most the first 4,096 logical UTF-8 bytes on a valid scalar boundary, unchanged. Empty usable text
does not authorize substitute input. Source selection and range interpretation remain inside
Syndic; App does not repeat history-title derivation or inspect provider/CAS history.

Preparation advances with explicit source-record and encoded-byte budgets and bounded resident
state. Each continuation reauthenticates its relevant witnesses; unrelated Home writes do not
restart the whole scan. Source drift discards that candidate and advances discovery. A prepared
candidate grants no backend or mutation capability by itself.

One process-owned coordinator belongs to the published App service graph. It starts parked with
the existing private publication gate and becomes eligible only after graph publication. It uses
the existing Home/runtime/capacity wake routes and no window worker or independent service registry.
It retains one discovery continuation, one preparation continuation and at most one admitted
flight, with no pending candidate queue or per-thread failure map.

One discovery page contains at most 32 thread records. A preparation step consumes at most 64
source records and 65,536 stored/decoded bytes; its source prefix remains capped at 4,096 bytes.
A finite source-owned pass has a fixed upper frontier and advances beyond every attempted thread,
including ineligible, stale, failed and unavailable targets. New arrivals wait for the next pass.
An exhausted pass sleeps until a meaningful source/runtime/capacity wake. Its own failure or quiet
poll is not a wake. Unrelated mutation never resets its continuation or starves later candidates.

The flight acquires existing noncritical projection-worker capacity, preserving the existing
steering reserve. It retains the exact source runtime/root interest, process identity and service
generation authorization. Capacity refusal waits through the existing capacity notification and
retains bounded discovery progress. Title work never loads or replaces a selected projection.

## Independent Backend Invocation

Maintenance qualifies an independent full-profile session to the original managed process through
the same release/configuration admission proof as ordinary projection work. It does not construct
an ordinary capture connection, register a Syndic binding or occupy the selected stream. Request-
only sessions cannot stream output and are ineligible. No new parser/profile or compatibility
path is introduced.

The flight creates one ephemeral backend thread in the exact immutable runtime/root. Its explicit
developer instructions contain only the fixed title-generation policy, replacing user-global
developer instructions through the pinned thread-start override. The prompt treats the exact
bounded input prefix as data. It contains no live conversation history, draft, global instructions,
CAS names or substitute text. The complete prompt envelope is at most 8 KiB. Title invocation uses
the existing streamed-input start and exact dispatch outcome; request/profile/instruction fields
are qualified in the managed-runtime fixture.

App consumes backend-normalized ordered provider operations, not raw protocol JSON. It selects
only the exact route's completed AgentMessage with FinalAnswer phase or absent phase; Commentary
and reasoning are not candidates. Exactly one completed eligible message is required across the
turn, followed by the matching successful terminal; multiple candidates are rejected. Delta/completion
repetition cannot duplicate text. It returns each original page lease synchronously and retains
at most 512 result bytes plus fixed parser/overflow state. Overflow, malformed text, wrong route,
incomplete output or unsupported activity refuses the candidate without truncation or repair.
Lexical framing remains backend-owned; any needed missing fact is a small typed normalization
extension. The complete result goes unchanged to Syndic's existing strict title validator.

Approval or tool activity fails title generation. Exact approval denial uses the originating
session's typed response where available; Unanswered or a dropped request is not denial. No GUI
approval broker is mounted and no ordinary durable stop authority is fabricated. Unsupported
activity cannot become successful title output.

The invocation has a 30-second monotonic deadline covering admission/start/observation, bounded
polling at most 100 ms apart for cancellation, and a separate cleanup budget of 5 seconds. Tests
may shorten these fixed deadlines through test-only inputs. Blocking calls use the remaining
budget. A deadline is failure, not remote terminal evidence.

## Uncertainty And Retirement

The move-only flight owns its original session, runtime interest, worker permit, candidate,
cancellation and eventual Home command custody. Cancellation first fences publication, then
requests exact unsubscribe when a loaded backend thread is known, closes only the maintenance
websocket and joins the original local worker. It never kills a shared managed process to clean
up a title. Local socket/worker drainage does not prove remote turn termination.

Dispatch whose terminal outcome remains unknown, or cleanup without matching terminal evidence after possible dispatch,
sets a sticky title-admission fence for this entire published graph before releasing original
flight custody. Retain exactly one compact graph/runtime/process/source-qualified uncertain
outcome; retain no session, connector, Home or worker capability after actual local drainage.
No further title invocation is admitted in that graph, even if its runtime later restarts. This
bounds unresolved remote maintenance work without a request journal or replay. Ordinary execution,
activation, reading and lower-precedence titles remain available.

Known successful-terminal invalid output is an ordinary failed attempt and advances discovery.
A later meaningful wake may prepare a genuinely new attempt; completion-unknown requests are
never replayed. A replacement graph may start fresh only after the original graph's existing
runtime/native disposal and publication prerequisites complete. This relies on the original
runtime owner, not on a title-supplied claim of remote closure. Failed local drainage retains its
original cleanup owner and blocks successful retirement; bounded deadlines never abandon it.

## Acceptance And Coherent Refresh

A valid result constructs the existing source-qualified GeneratedThreadTitle and submits exactly
one one-way Syndic attributes mutation. Current source/attributes conflicts discard the result;
they never overwrite an accepted title. Home commit uncertainty retains and reconciles that
original command through the existing coordinator before releasing its custody. It does not
regenerate a title to infer the outcome. Actual Home failure uses the existing global failure cut.

Acceptance wakes the existing Syndic summary and State catalog projection repair. Visible rows,
selected heading and lineage consume one later coherent prepared source. Selected metadata renews
through the existing observed-coherent publication even when transcript content is unchanged.
App never patches visible strings directly and title-specific failure never gates foreground use.

Acceptance covers strict output rejection; genuine bounded source selection and stale/competing
acceptance; fair discovery/capacity; independent foreground progress; exact instruction/profile
fields; unsupported controls; possible-dispatch sticky-fence races; page/worker/session release;
original Home reconciliation; private initial/recovery graph mounting and retirement; reopen; and
actual catalog/selected-title adoption. Independent semantic review spans the affected storage,
privilege, external-effect and shared-lifecycle boundary. Source/component evidence alone does
not qualify graph mounting or visible adoption.
