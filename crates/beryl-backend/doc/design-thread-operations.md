# Thread Operations

This supplement is normative only for its bounded backend thread-operation role and is governed by
[design.md](design.md). It does not independently declare engineering rigor.

## Bounded Thread, Configuration, and Model Operations

- The package exposes pinned `thread/start`, `thread/resume`, `thread/fork`, `thread/rollback`, metadata-only `thread/read`, `thread/unsubscribe`, ordinary post-admission `config/read`, and one-page `model/list` operations. It retains only their exact bounded request and response fields; it does not synthesize omitted fields or expose catalog, title, selected-thread, root, runtime, source-tree, turn, item, preview, or history authority.
- `thread/start` creates the pinned ephemeral backend thread from its closed start input; `thread/resume` attaches an exact CAS projection only for live execution/control, never activation or catalog proof; and `thread/fork` creates one backend thread from an exact source thread without deciding activation or displayed lineage. `thread/rollback` takes only an exact thread id and trailing-turn count and mutates that backend thread history only; it does not decide branch preparation, source editing, or any GUI workflow.
- Start, resume, and fork request metadata-only controls including `excludeTurns = true` where provided. Their lineage responses, and rollback/start responses, retain exact bounded thread identity, closed status, model, provider, and reasoning facts when the method supplies them; they never synthesize omitted facts. Turns, items, previews, paths, names, source trees, historical arrays, and bodies are discarded rather than becoming an alternate transcript. Resume and rollback reject a different returned thread id; fork rejects reuse of its source thread.
- `thread/read` retains bounded thread identity, closed status, required bounded provider identity, and optional bounded subagent nickname. It never synthesizes model or reasoning metadata. `thread/unsubscribe` preserves only `notLoaded`, `notSubscribed`, or `unsubscribed` and is not persistent-thread deletion. Thread-close notifications retain only bounded identity in source order. Backend names are not Beryl title authority.
- Ordinary `config/read` exposes only cwd-scoped bounded model and reasoning fields. `model/list` accepts at most 64 records per caller-requested page, retaining bounded id/display label, hidden/default facts, closed default effort, recognized-effort bitset, and one bounded continuation. It has no all-pages aggregation; descriptions, modalities, unknown metadata, and unknown efforts are discarded.
- Resume and fork failures expose a method-specific lineage verdict only when app-server supplies one through a machine-readable field. Other JSON-RPC errors remain unclassified: numeric code, diagnostic text, and repetition never infer source loss or retry authority.

## Streamed Start and User Correlation

- Streamed `turn/start` accepts one non-cloneable replayable descriptor source and compact header: exact source identity, immutable revision, declared item count, and descriptor-sequence digest. It accepts neither materialized input nor arbitrary JSON. Each pass yields one closed text-run or exact local-image descriptor and verifies the declared count and digest before completion.
- The V1 digest is SHA-256 over domain bytes `beryl-streamed-user-input-descriptor-sequence-v1\0`, declared item count as unsigned big-endian 64-bit, then every descriptor in ordinal order: one-based unsigned big-endian 64-bit ordinal; text `0x01`, 32-byte text proof, and unsigned big-endian 64-bit UTF-8 length; or image `0x02`, detail (`0x00` absent, `0x01` auto, `0x02` low, `0x03` high, `0x04` original), unsigned big-endian 64-bit path length, and exact path bytes. Source identity/revision, storage pages, escaping, and frames are excluded.
- The public start shape has only descriptor-backed text runs, exact local-image runtime paths, model, reasoning effort, and hidden developer instructions. It has no remote-image, raw JSON, arbitrary-input, collection, or caller-escaping escape hatch. Paths are never host-to-WSL inferred or copied; developer instructions remain hidden context, never user input.
- A foreground session installs one exact streamed-start `UserMessage` verifier before dispatch. It compares ordered text and image fields incrementally and returns only checked correlation metadata plus CAS item identity. Exact pinned source/schema evidence must prove complete input on matching `item/started` and `item/completed`; missing, reordered, regrouped, or unequal input fails closed. Echoed vectors and text are never retained.
- The verifier is removed after the matching response or connection failure. Poison before replay or bytes is nondispatch; after dispatch it invalidates the connection. A response does not fabricate lifecycle evidence.
- Non-idempotent `turn/start` distinguishes proven nondispatch, an exact provider response, and completion unknown after possible dispatch. Timeout, transport loss, response decoding failure, and response-identity failure after dispatch are never ordinary retryable rejection or delivery proof.
- Source/revision validation, source replay, serialization or masking, cancellation, and concrete transport failure remain distinct typed start causes. Nondispatch proves only that no request byte reached transport, not transience or timer-retry authority; deterministic precondition, serialization, source-validation, and cancellation causes remain available to the caller, while post-dispatch loss preserves completion unknown.

## Injection and Repair Adapter

- `thread/inject_items` accepts an exact thread id and one replayable revision-bound source for only the CAS-live canonical text-message subset: exactly one user/input-text or assistant/output-text item per message. It preserves order without starting or fabricating a Beryl turn and admits no raw item, extra field, unknown type, or CAS-private wrapper.
- Preflight and encoding agree on nonempty input and text, exact identity/revision/digest, at most 262,144 canonical UTF-8 bytes and 262,144 items, emitted in valid UTF-8 pages no larger than 64 KiB. Each page carries exact ordinal, role, declared length, offset, and terminal facts; item terminal is valid only at declared end, sequence terminal only on the final item terminal, and one exact EOF must follow. Source cancellation, broker unavailability, revision drift, dependency read failure, invalid durable source, and page-structure disagreement remain distinct from one another and from every identity, ordinal, role, length, offset, terminal, count, byte-total, EOF, or digest disagreement.
- Each injection failure consumes the fresh target. Before a request byte is accepted it is nondispatch; after possible dispatch it is completion-unknown and invalidates connection authority. Results distinguish request success, structured rejection, concrete transport loss, and completion unknown; only write/read/closed/process/WebSocket failure is transport loss. Rejection retains exact error code, one bounded truncated diagnostic, and private-error-data presence, never arbitrary message or raw data. Callers abandon the target after every failure and never retry injection in place.
- The private repair stream is available only when the caller transfers the sole non-cloneable same-thread, no-successor dispatch capability for its exact correlated terminal target. It sends exactly one experimental generated `ThreadTurnsListParams`: authenticated `threadId`, no cursor, `limit=1`, `sortDirection=desc`, and `itemsView=full`; it accepts only generated `ThreadTurnsListResponse`.
- The adapter structurally consumes and discards any bounded continuation cursor, never follows it, requests no adjacent turn, falls back to neither `thread/read` nor item history, enumerates no threads, retries no attempt, and exposes no normal history API. It accepts only one matching terminal turn with complete full-item semantics, exact terminal evidence, ordered item provenance, and source ranges, incrementally emitted through the same closed item union as live capture. Exact `0.146.0` schema/source evidence must establish that route; absent proof leaves the adapter unavailable.
