# Original Image Command Architecture

## Boundary And Source Evidence

This is readiness evidence for original-image Copy/Save, without runtime qualification.
The image [feature matrix](../features/image-assets/design.md) owns availability, exact-original
effects and focus. The image system routes independent source/effect custody to its normative
[original-command contract](../systems/image-assets/original-commands.md); App routes its worker,
adapter and shared atomic-file responsibilities through the
[image-processing supplement](../../crates/beryl-app/doc/design-image-processing.md).
The system/App retain `production-application/v2`; the feature's existing external-effect and
irreversible-operation modifiers remain applicable without an upgrade.

At Beryl `89fd6d6d`, `ImageSourceProvider::resolve` authenticates an exact occurrence and then
requires PNG dimensions under rendition limits. `open_verified` applies the rendition byte ceiling.
Those restrictions belong to rendition preparation and cannot determine exact-original eligibility.
The target separates common authentication/committed metadata from those presentation restrictions,
while reusing the existing same-open-file bounded verified sidecar reader and Home generation gate.

The pinned GPUI `93f0584c01` already supplies checked encoded-image publication and native Save
destination choice. Its package contract covers exact image bytes plus companion metadata, native
capacity/padding, acknowledged failure and an isolated Windows clipboard harness. The Save choice
records explicit overwrite authority for its exact accepted path. This phase needs no new GPUI
capability and makes no physical device or clipboard effect claim.

App's accepted text-resource `code_panel/save_writer.rs` demonstrates same-directory staging,
bounded writes, flush/sync and authorized replacing/non-replacing publication. The target shares
only those private file mechanics. Image and text adapters retain their separate authenticated
sources, cancellation/publication elections and result custody; the image worker never calls the
text command executor or replays its protocol.

## Consumer Routes And Preserved Contracts

Original-command work reads the image-system entry point, original-command supplement, feature
matrix and App original adapter/worker section. Native integration additionally reads GPUI's
checked clipboard and Save-choice contracts. Rendition work retains its existing rendition route;
decoder/native owners need no original-command policy. Storage/reference and generated admission
authority stays in the existing image-system entry point. No existing contract was removed.

Composer and transcript GUI compositions already require the preview's contextual anchor and
bounded anchored menu, ordered Copy then Save. Direct transcript marker commands use their context
menu. Existing inline disabled labels are implementation gaps, not an alternative target layout.
The preview widget's child-flow focus delegation and feature-owned exact origin/fallback mappings
remain authoritative. The feature now explicitly defines the transient checking-original state;
it does not infer command eligibility from a rendition or permit stale completion to enable a new
surface.

## Readiness And Implementation Gate

The target specifies one process command reservation, shared fixed media workers and source-stage
limits, independently verified exact originals, charged encoded Copy output, worker-owned atomic
Save staging, explicit foreground publication election, result custody and complete graph drain.
It also names typed disabled/failure outcomes, no automatic effect replay, actual mounted menu/focus
proof and isolation from the Operator's clipboard. Independent complete-boundary readiness review
accepted source authority, capacity/lifetime, publication election, native acknowledgement,
destination preservation, canonical placements and stale-safe focus. Existing dependency and
text-Save mechanics support the target; no unresolved material choice remained. This accepts the
architecture only. Byte, failure, lifecycle, native-effect and mounted-flow evidence remains required
for implementation acceptance, including existing text/table Save preservation after extraction.

No source, dependency, runtime test or native GUI is changed or executed for this architecture
boundary. Implementation and effect qualification remain the following plan phase; the accepted
[rendition qualification](bounded-image-rendition-qualification.md) is preserved independently.
