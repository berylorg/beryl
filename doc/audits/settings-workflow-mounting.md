## Status

## Implemented Boundary

The ordinary main-window toolbar exposes Settings after Exit. One process-owned controller
preheats the external Settings window; opening and main-window closure do not transfer its draft
or create a Session window record. Its native destruction receipt is awaited before final service
cleanup. Startup and runtime appearance budgets include the auxiliary window and replacement slot.

Each published service generation owns one finite five-key Settings baseline and applied source.
The window stages one whole draft, supports row Reset and atomic Apply/modified OK, and preserves
original command custody through observation, cancellation, retirement and same-home recovery.
Indeterminate scalar outcomes install their original Home registry capability before delivery.
Unresolved exclusions cover only the affected keys and cannot be cleared by a fresh raw read.

Ordinary instructions, compaction timeout, completion sound and composer autosave consume the
qualified applied source. Pending drafts do not change active values. Autosave publication keeps
one process-monotonic token across generation replacement and refuses unavailable timer admission
without disabling explicit flush.

Themes use bounded revision-qualified repository pages and the canonical ThemeEditor navigator.
Repository reads and writes run off GPUI through the generation-owned broker. Original repository
tickets and exact outcomes survive observation and retirement; definite preexecution refusal is
distinct from uncertain outcome. Save As preserves original editor ownership, staged values,
activation and appearance. Committed Save cleans the document draft independently of a later
authentication read. A document editor remains independent of later scalar activation changes.

Read-only qualification gates Apply/modified OK for an exact staged theme without allocating an
operation or claiming command custody. Actual Apply prepares again. After commit, exact durable
selection/document revalidation precedes publication. Failure retains the committed Settings and
prior coherent appearance with persistent feedback. Fresh Retry, eligible watch and active Save
publication consume retained Settings intent through the same appearance path. Stop Preview
supersedes older preview work before freshly validating the current durable theme; failure
preserves the displayed preview.

Appearance sources, callbacks and navigator focus/scroll leases remain exact across source,
window, draft, mount and projection replacement. GPUI drains only bounded in-memory theme hints;
nonempty work uses the existing exclusive appearance flight. Idle projection performs no Home
read or worker admission. Startup/recovery imports retained theme failures into Settings feedback;
an unrelated appearance-neutral repository completion cannot clear them.

Temporary worker custody preserves the generation's fixed set of published read facades, with
their original currentness checks. Restoring the mutable owner drops those retained facades;
genuine retirement still invalidates them. Initial command mounting and interrupted recovery
completion finish before appearance work can borrow the mutable owner.
