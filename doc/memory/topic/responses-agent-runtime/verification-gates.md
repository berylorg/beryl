# Reason For Investigation

Decide which remaining experiments could change architecture selection, reuse authentic direct
results, and avoid consuming quota on nondiscriminating stress. Separate service evidence from
decoder correctness, resource qualification and end-to-end agent quality.

# Outcome

Existing direct evidence is sufficient to recommend a conditional architecture direction, not
unconditional production adoption. No further live requests were made for this phase. Large
memory, crash and tool-policy questions need a selected local implementation; repeating HTTP
requests cannot establish those properties. Quality parity remains unproven and is an explicit
gate before committing to a reduced tool/model envelope.

This specification does not authorize production implementation or release the rework hold.
Any future prototype must be scoped in the root plan after the relevant architecture choices.

## Evidence Already Obtained

- Authentic subscription inference using the active account; usage reported Pro. No Platform API.
- Actual completed function and custom call/result round trips; custom prompt compliance was
  imperfect and remains recorded rather than being hidden by the successful transport result.
- Actual opaque reasoning reuse and actual streaming compaction continuation in Lite. Retained
  user text means the compaction test did not prove summary-only recall or long-task quality.
- Source-backed standalone search and representative image request succeeded. The first image
  body's framing remains unidentified; the second parsed JSON. No general image-streaming claim.
- Received field order, repeated payloads, empty terminal arrays, version-sensitive catalog and
  rejected request parameter are preserved in focused notes. The helper was deleted after use.

These results answer access and several practical ordering questions. They do not prove universal
field order, every event kind, a server-side output cap, production buffer bounds or safe retries.

## Before Unconditional Streaming Adoption

Required paths not yet covered directly include reasoning summaries, annotation/refusal payloads
and nonempty terminal output echoes. Determine which are required by the selected product/model
envelope. For required paths, use ordinary bounded prompts/source-guided requests when reasonably
available; do not provoke enforcement or claim mocks are service evidence. If a path cannot be
observed, explicitly choose supported bounded failure or keep adoption conditional.

The implementation must show a final destination before every potentially large required field,
or a fixed pre-identity bound with an explicitly accepted failure outcome. Do not convert fixed
bounds into overflow spools. Separately resolve sidecar versus indexed-record storage; the
existing hash-addressed sidecar construction is not already a final appendable request resource.

Offline decoder checks should fragment UTF-8/JSON/SSE boundaries, reorder fields, interleave
items, repeat deltas/completions, omit identities, exceed fixed prefixes, inject unknown variants,
truncate streams and fail storage at publication cuts. Test base64/decompression amplification
and outbound serialization. Measure high-water memory as payload size increases with fixed
concurrency and bounded retained UI. Those tests prove implementation behavior only, never what
the live service emitted.

## Agent Quality And Context Experiment

After choosing a candidate tool host, use one small synthetic repository task with explicit
acceptance checks: inspect files, make a bounded edit, run a focused check and explain the result.
Compare the chosen catalog-guided tool mode with any proposed simpler mode on the same task and
model. Record valid/invalid calls, correction loops, completion, changed files, cost/usage and
elapsed time. A plain-function success alone cannot justify removing required code mode.

For compaction, use a compact synthetic set of independent facts and a later task requiring them.
Inspect the exact post-compaction request to ensure the answers are not still present in retained
plain text before calling the result summary-only recall. Test one repeated compaction and one
approved model transition only if they distinguish proposed policies. Keep originals for exact
comparison; record omissions instead of reconstructing them with hints.

These are proposed experiments, not results. Building a credible tool host to perform them is
new work and must not be smuggled through the research hold. If the Operator wants quality proof
before broad design adoption, select a separately bounded experimental vertical slice first.

## Execution, Scheduling And Integration Qualification

Use deterministic local failure cuts for durable admission, possible dispatch, tool effect before
result commit, late stop, storage outage, duplicate results and restart. Exercise branch job
success/archive barriers and unknown delivery without assuming transport loss proves termination.
Test bounded child capacity and wait deadlocks locally before a live multi-agent task.

MCP qualification needs controlled local servers for schema refresh, collision, auth-required
unavailability, denied elicitation, oversized results and shutdown. Controlled fixtures are valid
implementation tests; they must be labeled as such and not reported as subscription observations.
Sandbox/path/PTY tests need each retained execution environment. License/dependency checks follow
the exact selected package set, not a generic claim that Rust reuse is safe.

## Live Budgets And Stop Conditions

Any additional research batch should declare its material question and fixed endpoint first.
Suggested starting envelope: one request at a time, at most four inference requests per question,
synthetic text inputs below 32 KiB, response cap 1 MiB and a 30-second local research deadline.
No additional image generation is needed to choose the current architecture. These are local
containment limits, not a guaranteed server token or weekly-quota cap: the subscription rejected
the tested output-limit field, and disconnect does not prove remote cancellation.

Stop the batch after an access denial/security challenge, unexpected side effect, rate limit,
ambiguous auth ownership, repeated malformed behavior or a result that answers the question.
Honor service retry guidance rather than immediately retrying. Do not refresh the active client's
token independently, scan alternate routes, increase caps repeatedly or escalate to stress.
Production quiet-stream behavior remains separate from disposable research deadlines.

## Deferred With Reasons

No concurrent login/revocation/account-downgrade test on the active account: architecture can use
explicit refusal/relogin and generation fencing, while such tests are disruptive. No deliberate
refusal trigger. No long-output flood, extensive benchmark suite or repeat image probe: these do
not currently discriminate the ownership options. No claim of coding quality, crash safety,
cross-platform containment or lossless all-event streaming until their actual gates pass.
