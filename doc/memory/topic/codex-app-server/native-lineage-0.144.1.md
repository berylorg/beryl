# Reason For Investigation

The Beryl-home rework requires CAS-native continuation, resume, fork, and rollback to remain the ordinary execution path. Beryl must prove that exact parent context is inherited without manually replaying Syndic history before admitting one-time recovery injection as a fallback only.

# Outcome

Codex App Server 0.144.1 preserved exact native lineage through same-thread continuation, process restart/resume, inclusive terminal-turn fork, full fork, rollback, and post-rollback resume without `thread/inject_items`, `additionalContext`, or another Beryl history channel.

## Live Provider-Boundary Proof

- Deterministic provider captures observed each inherited user and assistant canary exactly once with its original role.
- Same-thread continuation observed the first user/assistant exchange before the second user input.
- Restart/resume reconstructed the first two complete exchanges and placed the new user input after them.
- Fork with the first terminal turn id was inclusive: it retained that turn's user and assistant items and excluded every later turn.
- Full fork copied the complete effective source history into a distinct child thread without mutating the source.
- Rollback removed the requested trailing turns from effective history, retained earlier turn identities, and allowed a later turn to continue from the retained prefix.
- Restart/resume after rollback reconstructed the effective retained path rather than the logically removed suffix.
- The separate repository-owned Phase 8 probe reproduced continuation, restart/resume, terminal-prefix fork, and rollback behavior as part of twelve provider requests retained with per-request hashes.

## Boundary Semantics

- `thread/fork.lastTurnId` is an inclusive terminal-turn boundary. Exact branching must use a proven terminal persisted turn id.
- Omitting `lastTurnId` copies full effective history. A persisted mid-turn suffix can acquire an interruption boundary, so it is not a substitute for an exact terminal anchor.
- Rollback changes effective history in place and persists a rollback marker. It does not create a descendant or erase raw earlier rollout records physically.
- Native resume and fork inherit CAS's current effective context, including any lossy compaction already performed. They do not reconstruct discarded original bytes from Syndic.
- Fork and rollback have no idempotency key. An ambiguously completed request must not be retried blindly because it can create a second child or remove another turn.
- Public thread projection is lossy and cannot prove exact model-visible context. The live proof therefore inspected the actual provider request boundary.
