# Original Image Commands

This supplement is normative under [design.md](design.md). The
[image feature](../../features/image-assets/design.md) owns the command matrix and visible outcomes;
this contract owns source/effect custody across App, Home and GPUI. It inherits the image system's
rigor and composes with the feature's external-effect and irreversible-operation requirements.

## Independent Source Authority

An original command captures the exact eligible composer occurrence or transcript resource,
publication/revision, window/request identity and origin/fallback before asynchronous work.
Authentication uses the same ordinary owner-qualified occurrence and committed Asset metadata
checks as rendition requests. The authenticated original descriptor does not require a supported
decoder, dimensions, a rendition byte/pixel allowance, a CPU surface or a native image device.
Rendition preparation applies those restrictions separately after original authentication.
Generated resources require their existing owner-qualified admitted authority; unimplemented or
unadmitted producers remain unavailable and never fall back to an AssetId or provider path.

An admitted source worker opens the canonical sidecar on the exact healthy Home generation,
verifies exact length, SHA-256 and physical EOF, and consumes that same open file with bounded
seeks/reads. Original Save may stream any representable admitted byte length without a
whole-original allocation or a rendition-length ceiling. Copy additionally requires an admitted
complete encoded representation within its clipboard budget. There is no decode, transcode,
preview fallback, generic GPUI loader or temporary original-source copy.

Availability preparation returns compact readability/format/capacity facts tied to the captured
occurrence and generation. It closes its reader before completion and grants no reusable source
or effect capability. Actual Copy/Save freshly authenticates and verifies its own source. A stale
availability result cannot enable another occurrence or survive Home replacement. A source read
that fails after an enabled command reports that command's failure without changing image identity.

## Process Admission And Lifetime

The existing process media owner admits original availability and effect requests through one
shared original-command reservation. The immutable media configuration contains
`original_command_slots = 1`, `original_clipboard_total_bytes = 67108864` and
`original_clipboard_metadata_bytes = 4096`. The command slot covers queued work, active preparation,
prepared output, publication election and effect-result delivery; there is no uncharged queue or
second command registry. A refused reservation retains no source, buffer or worker.

A pending native picker retains that reservation until its actual completion is received, including
cancellation/error. Cancelling an App command fences its effects but does not prove that the native
picker closed. A live modal flow may keep retirement Pending until it settles; no unattended picker
timeout or inferred completion is required.

Original jobs share the fixed media worker cohort and its process path/verification reservations
with rendition jobs. A source job owns at most one configured sidecar I/O page. A waiting request
contains compact demand and weak attachment access; admitted workers alone upgrade source services.
No GUI entity, native window, file handle or Home service is retained in the process owner.
Prepared Copy bytes remain charged to the original-command reservation until consumed or dropped.
Save owns one same-directory staging file and bounded page rather than the complete original.

Window/request retirement cancels the exact operation. Attachment retirement refuses new work,
cancels pre-publication operations, wakes waiting workers, removes queued/prepared results and
drains active ownership before disposing Home services. Process shutdown additionally joins the
fixed cohort. Source handles and staging cleanup remain in worker custody. A command already
past its irreversible election retains its exact result custody through completion; cancellation
cannot relabel success as nonpublication or replay the external effect.

## Checked Copy

Copy supports only GPUI's checked exact encoded-image representations. Unsupported representation
and preflight over-limit are distinct disabled reasons, independent of rendition support.
The clipboard total includes owned encoded capacity, native image backing and companion metadata;
native padding is charged by GPUI. Preparation checks all arithmetic and allocation capacity before
allocating a complete output. Temporary ownership conversions and clones remain within the same
budget; an unaccounted second encoded value is invalid. The bounded source page is charged separately
through its source-stage reservation. Actual native backing refusal remains an acknowledged failure.

After preparation, foreground admission rechecks the exact live command/window/occurrence and
atomically elects publication against cancellation before invoking GPUI's checked write once.
Only the complete checked acknowledgement reports success. Native failure can leave changed or
partial clipboard content and reports failure; it never authorizes inferred restoration, deletion,
readback-based success or automatic retry. Tests use the owned isolated native clipboard station,
never the Operator's clipboard.

## Atomic Save

Save captures one native destination choice and its exact overwrite authority without retaining an
open source while the picker waits. Picker cancellation/declined overwrite performs no filesystem
effect. After acceptance, a fresh admitted worker authenticates the captured occurrence and source,
then copies exact verified bytes through one bounded page into a unique create-only staging file
in the destination directory. It flushes and synchronizes the stage before publication readiness.

Foreground admission rechecks the captured live command/currentness and elects publication against
cancellation. The same worker then publishes that prepared stage exactly once. A choice without
overwrite authority uses non-replacing publication; replacement is permitted only for the exact
accepted path with explicit native overwrite authority. No truncate-in-place or delete-then-rename
path is allowed. A publication failure leaves an existing destination unchanged or a new destination
absent, and cleans the owned stage. Cleanup failure remains explicit rather than claiming full
cleanup. A successful publication is reported only after the complete original exists; no later
optional operation may turn that committed effect into a claimed nonpublication. Path replacement
intent carries GPUI's documented path-level guarantee, without an extra file-identity lock claim.

## Qualification

Evidence covers originals whose renditions are unsupported, oversized or device-unavailable;
exact occurrence and Home fencing; shared capacity and cancellation through preparation/election;
all prepared-result/source/staging release paths; exact clipboard bytes and acknowledged native
failures in isolation; source verification failure; picker cancellation/declined overwrite;
existing/new destination preservation across write/flush/publication failures; and graph retirement
with pending operations. Mounted composer, transcript preview and direct contextual commands prove
the feature's focus/disabled/outcome rules. Independent complete-boundary review includes actual
source, clipboard, destination-publication and shutdown owners, with evidence limits stated.
