# Composer Paste Identity And Resource Configuration

Scope: captured composer paste qualification, 2026-10-05.

An initial producer derived persistent marker identities from a process counter starting at one.
Restarting the process could reissue identities from an earlier durable paste. Independent review
identified that process-local operation bookkeeping cannot supply durable object identity. The
correction generates one full random domain-identity seed during bounded preparation and retains
it through evidence and staging replay; checked ordinals produce stable identities within that
operation. A later preparation gets a new seed using the app's existing identity convention.

The first paste queue also used a lazy hardcoded capacity and borrowed the widget's mutation page
ceiling for image sidecar work. These limits did not consume the startup-owned configuration
required by the image system. The correction constructs validated positive paste queue and
sidecar page values at startup, retains them with the process source owner and transfers that
configuration through recovery. Queue reservation precedes acquisition; sidecar work uses its own
configured page ceiling.

Private clipboard correlation and storage failure need distinct dispositions. A mismatching
fallback text is observable replacement and expires only its exact captured token; unrelated
destination refusal preserves eligibility. Fresh-image storage failures require storage feedback
rather than a generic unsupported-source message. The corrected artifact passed complete
canonical qualification and independent completion review; see
[accepted evidence](../audits/composer-marker-feedback/captured-paste.md).
