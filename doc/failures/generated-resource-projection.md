# Generated Resource Projection

Composed native qualification proved real generated file admission and atomic State Published /
Syndic Asset publication, but the subsequent actual selected-transcript attachment contained no
generated image. Synthetic mounted lifecycle cases could not expose the missing producer of those
prepared facts.

`mutation/transcript/publication.rs` skips every canonical item whose `projection_source()` is
absent. `CanonicalItemRecord::projection_source()` explicitly returns None for GeneratedMedia.
The existing `ItemProjectionSetRecord` requires `ProjectionTextSource` and a Markdown parser
checkpoint; that source admits only composer content or provider narrative. There is no genuine
non-text generated-resource projection authority. App's Empty-payload mapping is consequently
unreachable from actual transcript construction, in the original thread as well as inherited views.

The decisive native case is
`generated_coordinator_inherited_branch_uses_prepared_selected_view_for_original_and_rendition`:
the real parent output is published, a child is created from its complete tail, and the actual
elected prepared transcript has no generated projection. Its missing-occurrence failure is not
ordinary read drift and must not be hidden by retries or fabricated prepared records.

The recommended repair is an explicit generated-resource branch in item-projection authority and
its canonical encoding, validation, membership and transcript publication. It should produce one
stable non-text image occurrence from resource birth through Pending, Admitted and Unavailable,
including ordinary freeze and inherited views. Text parsing retains its real text-source branch;
generated resources carry no invented content, marker, byte range or parser checkpoint. Reuse
the existing projection families and preserve the closed family inventory. Exact schema shape and
bounded construction must be fixed in owning Syndic contracts before implementation.

Operator approved the clean explicit generated-resource projection repair. The owning Syndic
history/V7 contracts now define its tagged source/set, stable occurrence, byte shape and bounded
publication; the
[active plan](../plan.md) retains execution and qualification. This note is diagnostic evidence,
not schema authority, and authorizes no migration adapter or fixture-only workaround.

Qualification must respect the independent asset and history frontiers. A native test initially
waited for full finalization while deliberately withholding generated admission, then attempted to
create an inherited Pending view. The actual generated occurrence and frozen current set existed,
but PendingAsset correctly kept the finalized frontier behind. Ordinary branch creation requires
a complete source tail and rejects that setup. The corrected sequence qualifies Pending lifecycle
and stale election in the original view, admits the same occurrence, then creates a legal branch
and authenticates the inherited original/rendition. Do not weaken completeness or fabricate an
incomplete inherited fixture to obtain this evidence.
