# Scope

Growable composer content and marker-operation admission during the Beryl-home rework.

# Invalidated Assumption

The bounded-memory requirement had been strengthened into an uncapped logical-edit promise while
the marker readiness protocol retained an entire operation's evidence under fixed durable quotas.
Paging that evidence bounded RAM but could not make an operation exceeding its total quota finish.

# Evidence

The composer and bounded-resource contracts promised uncapped edits. Syndic required all readiness
associations through evidence EOF before proof issuance and builder consumption, while limiting the
home to 65,536 retained associations and 67,108,864 encoded bytes. A larger eligible rich-marker
paste could therefore exceed admission capacity even when the existing draft and clipboard
representation were otherwise valid. This was a documentation contradiction, not an observed memory
leak or a demonstrated failure of ordinary text editing.

# Accepted Correction

Keep datasets and drafts independent of resident working-set size. Permit an explicit generous
individual marker-operation profile, distinguish its permanent size limit from shared-capacity
contention and storage failure, and preserve atomic rejection. Retain paged durable trees and
bounded presentation rather than expanding the protocol solely to preserve the stronger promise.
The composer feature, bounded-resource system, Syndic system, and Syndic package own the live
contracts; this note supplies no limit or implementation authority.

# Remaining Verification

The owning implementation slice must prove the refusal classification, unchanged candidate and
editor state, bounded cleanup, and bounded residency as the existing draft grows. A documentation
correction alone does not establish those implementation outcomes.
