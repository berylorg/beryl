# Composer History Fixture Protection

Scope: mounted rich composer cut/Undo qualification, 2026-10-05.

A fixture seeded an image marker through a legacy direct builder, then reactivated that root as
the editor candidate. Copy, cut, token promotion and the current surface all appeared valid, but
one mounted Undo left the cut successor unchanged. Waiting for semantic quiescence did not fix it.

Focused history dispatch proved that the shortcut emitted the correct operation and current
frontier. Host history preparation rejected it with `InvalidRequest`: the seeded predecessor's
marker maximum was not covered by its draft image label protection head. The fixture had bypassed
ordinary fresh-asset evidence, assignment and protection. This was correct storage refusal, not
evidence that the history adapter should loosen authentication.

Seed history-sensitive marker fixtures through actual admitted Asset metadata and the mounted
evidence/readiness/staging path. Assert that label protection covers the predecessor's marker
maximum before exercising cut and history. Keep one real Undo, exact predecessor-root equality
and token expiry assertions. Fixed draw counts or extra Undo requests cannot repair invalid
source authority.

The corrected case passed with one mounted Ctrl-Z. See the
[qualification record](../audits/composer-marker-feedback/private-copy-cut.md) and
[history contract](../../crates/syndic-storage/doc/design-draft-storage.md).
No production protection or history semantics changed. Full clipboard paste and large-draft
refusal qualification remain separate planned work.
