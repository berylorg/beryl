# Scope

Checkpoint 3 Phase 13 standalone CAS image-generation capture.

# Invalidated Approach

The exhaustive `ProviderItemV1` correction initially treated every upstream public string as an
admitted durable field. Because `ImageGeneration.result` is the generated image's base64 payload,
the proposed correction was to decode or sidecar-admit that field during live capture and retain a
typed resource reference in its place.

# Evidence And Failure

Pinned Codex source proves that `result` contains base64 image data and that `savedPath` is a
separate field. The Operator then clarified Beryl's intended integration boundary: image-generation
base64 is discarded at incoming WebSocket/JSON processing, only `savedPath` crosses into Beryl's
normalized item, and generated bytes are never stored in Fjall.

The proposal therefore confused the upstream wire schema with Beryl's deliberately narrower
normalized history contract. It would have added a second image-ingestion path, weakened the
existing CAS file-handoff boundary, and made binary transport data part of provider history.

# Course Correction

Restore a bounded ingress decoder that consumes standalone image-generation `result` without
constructing or retaining its string. Remove `result` from the normalized backend item and from the
Syndic provider-frame grammar. Preserve exact lifecycle timestamps, status, revised prompt,
`savedPath`, and CAS/runtime provenance. Later asset admission reads the exact runtime-local path and
publishes Beryl-owned sidecar authority; a missing or unusable path has no base64 fallback.

## Post-Buffer Exclusion Was Still Too Late

The first replacement decoder structurally removed `result` before constructing a retained
`serde_json::Value`, but the WebSocket transport had already accumulated the complete raw message in
one `Vec<u8>`. That avoided decoded and downstream copies while still making peak transport memory
scale with the base64 payload. The Operator clarified that this does not preserve Beryl's established
drop-as-soon-as-possible behavior.

The final boundary must feed incremental JSON consumption directly from bounded WebSocket payload
chunks and discard the target string as it is parsed. Only fixed transport/parser buffers may retain
those bytes. Moving the message-sized allocation elsewhere, imposing a smaller accepted image limit,
decoding under a cap, or falling back to `result` would be workarounds rather than the required
architecture.

Arbitrary JSON member order cannot be preserved simultaneously with one-pass early discard and
exact preservation of non-target `result` fields. Pinned source plus an installed-runtime wire proof
resolved this without a buffering workaround: official CAS 0.144.1 emits notification `method`,
lifecycle `item`, and item `type` before the target payload. Beryl pins that producer order and fails
closed if a future or nonconforming producer makes the field ambiguous. The retained proof is
`doc/memory/github.com/openai/codex/commit/44918ea10c0f99151c6710411b4322c2f5c96bea/image-generation-wire-order.md`.

The corrected authority lives in `doc/systems/cas-live-syndic-transcript/design.md`,
`doc/systems/image-assets/design.md`, the backend/app/Syndic package docs, the active rework tracker,
and Phase 13 of `doc/plan.md`. Source evidence remains in the pinned Codex memory note
`image-generation-result-payload.md`.

# Remaining Proofs

- Prove the base64 value is absent from retained JSON values, deferred queues, normalized items,
  diagnostics, logs, provider frames, and Fjall records.
- Implement and verify fragmented WebSocket frames, escaped strings, malformed JSON, oversized
  input, stdio compatibility input, and missing or empty `savedPath` fail or normalize exactly.
- Prove generated-file admission uses exact runtime/process/session provenance and never treats the
  path itself as durable asset authority.
- Prove submitted-user image echoes correlate with existing asset ownership and that explicitly
  typed dynamic-tool or MCP inline-image payloads either cross an admitted asset boundary or keep
  history incomplete; none may enter the generic structured-value codec as Fjall image bytes.
