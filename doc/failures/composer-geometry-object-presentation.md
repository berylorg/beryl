# Composer Geometry Object Presentation

## Invalid approach

Treat a terminal target whose retained inline-object fragments outlive their source object pages as
ordinary surface-capacity saturation, then shrink the realization extent through the existing
capacity fallback.

## Decisive evidence

The focused exact-priority fixture placed 96 objects at one source anchor with object residency
limited to 16. Exact geometry correctly streamed to the requested gap between objects 47 and 48,
but terminal surface publication could no longer resolve every retained inline-object fragment from
the projected resident pages. Capacity fallback reached the minimum one-line realization extent and
could not converge because the indivisible visual line still contained more objects than page
residency. The mounted scale fixture independently completed all 257 durable marker edits with a
flat process footprint, then exposed the same missing realized-object publication at its final
viewport hit test.

## Rejected corrections

Pinning the prior object page would exceed the configured residency bound at a continuation boundary
and couple geometry correctness to cache capacity. Reclassifying the missing fact as retryable
capacity does not work for an indivisible line. Expanding object residency would only move the
failure to a larger same-anchor run.

## Corrected boundary

Exact geometry must own one compact authenticated presentation record for every retained target
inline-object fragment and transfer the two atomically to the coherent surface. That projection is
fully accounted and bounded by retained target fragments. Generic resident object pages remain the
separate bounded authority for gap proofs, edits, clipboard, and continuation, so presentation
ownership neither weakens proof rules nor retains the complete run.

## Priority refinement correction

An exact-index response that mapped a priority endpoint previously cleared the source anchor while
leaving the old block target unchanged. A far same-anchor object gap could therefore be found
correctly and then replaced by the first capacity-sized block window during refinement. Retaining
both the stale block window and the distant priority window would have made target residency
additive and unbounded across increasingly distant requests.

The mapped endpoint now retargets the ordinary block window when it lies outside that window.
Unmapped and end-of-source priority endpoints retain a source anchor only until the exact scanner
finds the containing fragment; the scanner then resolves that anchor into the same block target and
continues normal bounded viewport retention. The priority anchor is therefore a one-time exact
resolver, not a second residency domain.

## Mounted acceptance fixture correction

The first large-scale rerun after geometry-owned presentation still reported no object hit even
though the coherent surface retained bounded realized objects. The fixture had mounted its composer
in an unconstrained test-window root, allowing GPUI to replace the 320 by 640 bootstrap geometry
with the larger window bounds, while the assertion searched only the original 320 by 640 prefix.
That result did not invalidate presentation ownership or hit-test identity.

The fixture now owns an explicit 320 by 640 mount box and derives its hit-sampling bounds from the
same constants. Mounted layout, scroll coordinates, and the searched viewport therefore share one
deterministic geometry contract.

## Mounted viewport admission correction

The deterministic mount exposed a second fixture-sensitive transition: prepaint reported the same
viewport extent while an identical extent was already pending through target admission. Treating
that observation as a new target invalidated the otherwise coherent pending surface and rejected
finite widget bounds as incomplete.

Viewport extent admission is now idempotent for both the committed desired extent and an identical
pending extent. A repeated layout observation therefore joins the existing transition instead of
manufacturing a competing one, while a genuinely different extent still follows ordinary bounded
admission.

## Mounted activation-coordinate correction

The scale fixture first replaced a fixed four-tick post-click delay with a bounded wait for the
observable active-object state. The complete scale rerun proved that timing was not the cause: no
activation arrived within the work limit.

The fixture had authenticated an object at a sampled point inside the mounted viewport, then
discarded that point and clicked one pixel from the object's logical hit-bounds origin. A partially
clipped object can have a visible authenticated sample while its logical origin lies outside the
widget. The semantic surface also extends beneath the rendered scrollbar's invisible right-edge
hit lane, where the scrollbar deliberately consumes pointer input. The range input correctly
receives no object pointer event in either case.

The fixture now samples outside the live scrollbar hit lane, confirms the surface is still current
and interactive, clicks the exact in-viewport point that produced the authenticated composite hit,
and waits for the observable activation with an explicit finite work limit. This tests the real
mounted pointer route without disabling production occlusion or making scheduler timing and
unclipped logical geometry part of the acceptance boundary.

Those fixture corrections removed ambiguous pointer coordinates but did not settle activation in
the complete 257-object run. They were necessary acceptance cleanup, not the production root cause.

## Exact interaction-anchor correction

Pointer selection preserved the clicked object's exact leading and trailing composite gaps, but the
replacement target transition discarded that source anchor whenever the prior coherent surface
could already map it. The next geometry job therefore retained only a byte target. With 257 objects
at the same byte anchor and generic residency capped at 48, an ordinary forward slice could satisfy
byte coverage while containing a different set of object orders. Active-object preparation then
rejected the incomplete exact selection and retried without recovering the lost witness.

An inline-object Set interaction now always contributes its full selection-head source position to
ordinary target replacement and index-response successor construction. The existing exact scanner
uses that bounded gap witness to choose an earlier checkpoint, page forward to the precise order,
resolve the anchor once into the ordinary block target, and release unrelated pages. No object page
is pinned and no separate lookup or residency domain is introduced.

The focused regression retains presentations for 96 same-anchor objects while generic residency is
limited to 48, chooses a visible object absent from resident object pages, and proves its exact id
and order activate through bounded eight-object paging.

## Detached owner accounting correction

After exact activation succeeded, the complete scale fixture reached final disposal and expected
the still-live input entity's aggregate owned bytes and items to be zero. Range realization
diagnostics intentionally include the fixed inline widget plus its empty residency and geometry
owner records, so a Rust entity retained by the fixture cannot occupy zero memory even after every
dynamic resource is released.

Final acceptance now requires every dynamic ownership field to be zero while the detached entity
remains inspectable, allowing only the aggregate owner charge and the fixed empty exact-geometry
owner record. It then downgrades and drops the fixture's target and input handles, advances one
bounded render boundary, and proves both weak entities are gone. This distinguishes exact dynamic
lifecycle release from physical reclamation of the owner object itself without hiding retained
pages, requests, geometry publications, candidates, custody, or queue backing.
